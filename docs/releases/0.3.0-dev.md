# PhoneForm AI PC 0.3.0-dev

2026-10-22 · Windows 11 x64 · 內部試用開發版 / Internal evaluation development build.

## 繁體中文

本版本改善人工範本設定、標記辨識及來源追溯，以本機 MSI 交付。本輪不建立 GitHub Release；原有兩個版本的標籤、Release 及附件保持不變。

原碼已以 Nickwong-kyoaka 推送至 `main`；[遠端核對](../../output/validation/0.3.0-github.json)確認原兩版附件與標籤未變。[臨時資料清理](../../output/validation/0.3.0-cleanup.json)已完成，Git 僅保留產生／核對程式及匿名摘要。

- 不要求額外空白問卷參考，也不以空白／已填影像相減辨識答案。整組選項與矩陣可自動分格，再拖動整組、行列分隔線與個別框；同頁同題型、相同選項數可複製設定，印刷數字核心須重新確認。
- 方框勾叉與圈選印刷數字使用分開的分析方式；逐選項保存有標記、無標記、不確定或未處理，以及原因、測量與座標。整題所有選項均確定時才產生候選；歧義、塗改或不完整裁圖轉人工。方框裁圖須保留邊框周圍空間，貼邊裁圖會拒識。
- 辨識設定確認後成為不可變版本。任務固定設定、引擎、參數與影像指紋；採用候選保存實際任務及證據引用。重新辨識只針對未確認問卷，保留人工答案與既有歷史快照；舊版未綁定候選不會冒充新版結果。
- 校準預覽可限定目前題目組，不寫入正式答案或任務。其他題目尚未完成設定不會阻擋合法題組的預覽。設定發布後若草稿清理失敗，可只重試清理，不重複發布。
- 局部題目文字 OCR 提供待確認建議，不自動翻譯或合併題目；數字／日期使用局部答案區與格式校驗。中文手寫與自由文字繼續人工輸入。
- 保留三語介面、獨立 Excel 標題語言、加密編輯恢復、人工覆核、四表 Excel 與快照規則，並加強未套用編輯與快捷保存的保護。

### 1,000 份資料負載實測

此測試建立 1,000 份、每份 2 頁及 9 個答案目標的匿名資料，走人工覆核倉儲流程，並共用 2 張影像。它驗證資料負載，不量測機器辨識或獨立掃描吞吐；不將這次可選規模執行另加到 137 項回歸測試總數。

| 測量 | 本次結果 |
|---|---:|
| 收集與人工覆核資料寫入 | 497.790 秒 |
| 三語工作簿匯出合計 | 3.948 秒 |
| 整次執行 | 510.658 秒 |
| JVM heap pool 峰值 | 277,730,480 bytes，約 264.9 MiB；不是整個程序的記憶體佔用 |
| 完整提交清單讀取／覆核摘要讀取 | 30.0／2,188.7 毫秒 |
| 程式端搜尋，25 次樣本 | 平均 0.838 毫秒，P95 1.290 毫秒 |
| 加密工作區重開／後續資料核對 | 192／3,749 毫秒 |

重開後核對 1,000 筆清單，抽核 3 份的 27 個答案值及 3 個匯出快照。獨立核對三語工作簿合計 3,000 筆回應列與 27,000 個答案值；每語 14,056 項、合計 42,168 項檢查全部通過，每語各 1,000 個前導零文字及公式形狀文字均保留。

目前倉儲沒有分頁或資料庫搜尋 API；上述搜尋是在完整讀取後做程式端篩選，不是資料庫搜尋或 GUI 延遲。這次未量測縮圖載入、真實滑鼠捲動或新界面完整 1,000 份操作。

以上辨識分數來自匿名生成像素，標籤在執行辨識前固定，未以人工答案回填機器結果。候選覆蓋率表示清晰測試題組中產生正確候選的比例；其餘轉人工。這些數字不能推論真實掃描、通用手寫或實際使用環境的準確率與吞吐量，候選仍須人工核對。

依使用者目前偏好，後續工作簿以答案及 OOXML 核對為主，不在每次檢查時自動開啟 Microsoft Excel。本次沒有新增原生 Excel 開啟通過宣告。完整三語手動流程、100%／150%／200% DPI、完整滑鼠鍵盤操作、乾淨 Windows 安裝／升級及其餘實機故障驗收仍待完成。

## English

This build improves manual template setup, mark recognition and source traceability. It is delivered as a local MSI without creating a new GitHub Release. Both existing tags, Releases and their assets remain unchanged.

- No additional blank-reference questionnaire or blank/filled image subtraction is required. Generate option or matrix cells, then adjust the group, dividers and individual regions. Copy settings between compatible questions on the same page; copied printed-digit cores require renewed human confirmation.
- Checkbox ticks/crosses and circled printed digits use separate analysis. Each option records its decision, reason, measurements and coordinates. A question produces a candidate only when every option is determinate. Ambiguity, cancellation and incomplete crops require human review. Checkbox crops need space around the printed border; crops touching the border are rejected.
- Confirmed recognition profiles are immutable. Jobs pin their profile, engine, parameters and image fingerprint; accepted answers retain actual job/evidence references. Reruns apply to unconfirmed questionnaires and preserve human answers and historical snapshots. Legacy unbound candidates are not presented as new versioned results.
- Calibration preview can target the current question group without creating production answers or jobs. Incomplete settings elsewhere do not block a valid group. Publication and editor cleanup have separate recovery paths, so cleanup retries do not publish twice.
- Local question-text OCR produces suggestions for human confirmation without translation or automatic question merging. Numeric/date recognition uses local answer regions and format checks. Chinese handwriting and free text remain manual.
- Three interface languages, independent Excel-heading language, encrypted edit recovery, human review and the existing four-sheet/snapshot rules are retained, with additional unapplied-edit and shortcut-save protection.

### Measured 1,000-record workload

The generated workload contains 1,000 records, each with 2 pages and 9 answer targets, using human-review repository operations and 2 shared images. It measures data handling, without measuring machine recognition or independent-scan throughput. This opt-in scale run is reported separately and does not increase the 137-test regression total.

| Measurement | Observed result |
|---|---:|
| Collection and human-review writes | 497.790 seconds |
| Three-language workbook export combined | 3.948 seconds |
| Complete run | 510.658 seconds |
| Peak JVM heap pools | 277,730,480 bytes, approximately 264.9 MiB; not total process memory |
| Full submission-list read / review-summary read | 30.0 / 2,188.7 milliseconds |
| Client-side search, 25 samples | Mean 0.838 milliseconds; P95 1.290 milliseconds |
| Encrypted workspace reopen / subsequent verification | 192 / 3,749 milliseconds |

Reopening verified the 1,000-record list, sampled 27 answer values from 3 records, and checked 3 export snapshots. Independent three-language workbook auditing covered 3,000 response rows and 27,000 answer values: 14,056 checks per language, 42,168 total, all passed. Each language retained 1,000 leading-zero text cells and 1,000 formula-shaped literal text cells.

The repository currently has no paging or database-search API. Search timings measure client-side filtering after complete reads, not database search or GUI latency. Thumbnail loading, physical scrolling and a complete 1,000-record UI journey were not measured.

Recognition scores apply only to anonymous generated pixels with labels fixed before detector calls. Human answers were not substituted into machine results. Candidate coverage is the proportion of clear test groups receiving a correct candidate; other groups require human entry. These results do not establish real-scan accuracy, general handwriting support or production throughput. Candidates still require human review.

Following the user's current preference, subsequent workbook checks focus on answers and OOXML rather than automatically opening Microsoft Excel every time. No new native-Excel opening pass is claimed. Full manual journeys in three languages, 100%/150%/200% DPI, complete keyboard/mouse coverage, clean-Windows installation/upgrade and remaining physical-machine failure checks are pending.
